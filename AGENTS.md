- Athena logic lives in src/lib/athena (data, deterministic engine, provider interface); records are permission-filtered before any output is computed; signals are observations only and hypotheses stay unverified; approvals are a pure local reducer.
- The prototype stays isolated: synthetic data only, no database or auth, and no EcoNest/Pendia connection. The deterministic analysis is local and makes no network calls; the only possible external call is the optional, off-by-default, server-side Meta request described below.
- Async Meta responses are shown only for the role, scenario and request they were issued for (src/lib/athena/meta/requestGate.ts, used by MetaPanel); any role/scenario/workspace change discards in-flight results.

- Meta model integration lives in src/lib/athena/meta (pure contract + server-only adapter) and is called only via src/lib/athena/meta.functions.ts; it requires server env META_MODEL_API_KEY plus META_MODEL_ENABLED=true plus per-run user confirmation; record scope comes only from the server-owned SERVER_ROLE_WORKSPACES map keyed by a submitted demo role id (client workspace lists are ignored; demo filtering, not authorization); it sends one request with no retries, and every output is schema- and citation-validated against permission-filtered records — so nothing reaches the model or the UI without the gates.
- Three-lane Meta output (src/lib/athena/meta: findings.ts, numericGrounding.ts, contract.ts): (1) verified findings are rendered by Athena on the server from verified facts (engine computeFacts over authorized records, ids `F-<metric>`) and returned with the result — the model never authors them; (2) interpretations are Muse Spark text, always `verified:false`, with `refs` to fact ids; (3) proposed actions are Muse Spark text with `refs`, `requires_human_approval:true`, never executable. The model sends no observations, numeric claims or record citations (v1 shape is rejected); citations are derived server-side from the referenced facts. Model text may contain no numerals at all (strict rule; NFKC-normalized, non-ASCII numerals rejected; record ids, Q1-Q4 labels and reporting-period references such as "Q3 2026" / "FY2026" / a clause-final "in 2026" exempt — only years from the authorized period labels). The prompt is facts-only (VERIFIED_FACTS + PERIODS); the adapter blocks any run where an authorized record is not covered by a fact. The hidden-record/source leak check compares Unicode-normalized keys (leakKey: NFKD, invisibles, marks, case, separators), and one 30 s deadline covers the request and the full response body (one attempt, never retried). Known gap until the Phase 2B-2 lexicon guards: contradictory or magnitude prose without digits, and prose about unauthorized domains, can still appear inside the unverified lanes (labelled unverified, shown beside the verified findings).
- Semantic guards (src/lib/athena/meta/semanticGuards.ts, Phase 2B-2): model text (interpretations, proposed actions, gaps) is REJECTED, never rewritten, when it (1) makes a directional claim whose subject is an authorized metric and contradicts its verified finding — the subject is resolved conservatively (head noun in "revenue from new leads", appositives dropped, non-metric heads like "revenue concerns"/"pressure on revenue" skipped, ambiguous binding yields no claim); habitual/generic statements, idioms, questions, conditionals, comparatives, imperatives and monitoring directives are not claims about the verified period; (2) states an unsupported magnitude — percent words, multiples, folds and spelled movements always, but halves/fractions/"N times"/scale words/"twice" only where they describe a metric (process language like "twice a week" or "split in half" passes; actions and gaps additionally need a movement/target word); (3) makes a directional claim about a metric or department outside the role's authorized scope (neutral mentions allowed). A metric the role is authorized for but that has no data in the scenario is reported as "unavailable data", not "unauthorized". Client-visible errors are generic: they never contain record ids, source labels, fact ids, unauthorized metric/department names or model text; only safe category codes (leak, ref, schema, numeral, direction, magnitude, domain, unavailable, ...) are kept for server-side logging. Verified findings stay server-generated and unchanged. Residual limits are in RESIDUAL_LIMITATIONS. Evaluation provenance (semanticGuards.test.ts, semanticIndependent.test.ts, semanticDisclosure.test.ts): the author-written corpora were tuned against and are regression only; the independent-review and blind sets are reported separately with their first-contact results in the file header. None of these is a general-population false-reject or bypass rate.
