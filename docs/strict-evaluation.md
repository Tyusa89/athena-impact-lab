# Strict pipeline: offline end-to-end evaluation (G3)

`src/lib/athena/meta/strictEvaluation.test.ts` runs every fixture through the real `runStrictAnalysis` (authorize, scoped prompt, one fake-model call, strict validation, uniform public rejection) on synthetic evidence. It is test-only: no production code was changed, there is no second pipeline, no network, no live model and no new dependency. The strict path itself is still inactive (nothing live calls `runStrictAnalysis` or `validateStrictOutput`).

## Method
- **Worlds** (reused demo scenarios, roles and policy factory, plus the customer-support dataset built through the real importer and ledger): exec, marketing, ops and finance roles; marketing restricted to leads with CAC granted as discoverable but without data; the quality-only scenario; the support desk with all departments and with Support only.
- **Fixtures** (101): a table of id, description, class, world, fake model reply and the exact expected outcome (accepted, provider error, or the exact set of internal diagnostic categories). Classes: `valid`, `security`, `usability`, `limitation`, `policy`.
- Each fixture is executed twice (determinism) and the fake provider counts its calls.

## Hard security gates (any violation fails the suite)
1. No accepted output contains a record id, source label, or the fact id or label of a metric the caller may not use (an explicitly granted discoverable metric may be named).
2. Every rejection is the one fixed public response, byte for byte, with no category, id, label or model text; a provider failure never echoes a secret.
3. Every accepted interpretation and recommendation obeys the H2.4b exact-reference rule (checked independently of `refsConsistent`, with the same vocabulary matcher), and its `supporting_ids` equal the records of the cited facts as rendered by the server.
4. Every explicit affirmative causal claim in the G2 set is rejected as `causal`.
5. `verified: false` and `requires_human_approval: true` hold on every accepted output, and replies that violate them are never accepted.
6. Repeated runs are identical.
7. The legacy path is unchanged (it still accepts what the strict profile rejects and keeps its detailed messages); the legacy goldens run in `golden/golden.test.ts` in the same suite.
8. The fake provider is called exactly once per request.
9. No network request is attempted.

## Usability measurements (reported, not thresholded)
The test prints valid-fixture acceptance, the false-positive rejection rate, the not-accepted rate on the security set, the known-limitation acceptance, the count of legitimate-uncertainty rejections, and accepted/rejected/error counts by world. These are measurements of a fixture set I chose, not a readiness score.

## Pinned current behaviour that is NOT protection
`limitation` fixtures (desired: reject, observed: accepted) are pinned so a change is noticed; they are not counted as evidence-integrity protection:
- a misleading non-numeric claim with correct citations (C10);
- ~~a generic recommendation or hypothesis citing an unrelated fact (C11, C12)~~ (resolved in G4.6, see below; the two fixtures are now `security` rejections);
- implicit causal wording: "hurt", "triggered", "as a consequence of" (D11-D13).

`policy` fixtures record an undecided product decision, not a verdict. E17 and E18 were decided in G4.7 (see below) and their fixtures were reclassed; no `policy` fixtures remain.

`usability` fixtures are legitimate wording that is currently rejected (fail closed): hedged Tier 1 causal wording (D14), "possible causes include" (D15), a denial rejected by the direction guard (D16), and a natural short form that is not a catalog alias, "satisfaction" for customer satisfaction (A28b).

## Limits of this evaluation
- Fixtures are synthetic and written by hand; a measured rate describes those fixtures only.
- The model is a fake, so this evaluates the validators and plumbing, not model behaviour.
- Gate 3 re-uses the production vocabulary matcher, so it checks the rule, not the vocabulary.
- Mention-level consistency and wording-based causal detection are not semantic verification; that is unchanged.

## G4.6: evidence-integrity hardening (offline; the strict path is still not promoted)
Four changes, all in the STRICT profile only. The legacy path, its detailed messages and the goldens are unchanged. `evidenceIntegrity.test.ts` holds the regression tests (13 of them fail if the source changes are reverted; the rest are positive, limit and characterization tests).

**C11/C12: generic citation integrity (`refConsistency.ts`).** A sentence that names no metric still has to cite at least one fact (schema), and `supporting_ids` are derived from whatever it cites, so an unrelated fact used to be shown as supporting evidence. Two deterministic rules now apply to such sentences, and a sentence that triggers neither still passes:
- *Department*: if it names a department (or a metric with no verified fact, whose owner counts) and the caller has at least one verified fact in a named department, at least one cited fact must belong to a named department. "Review the sales strategy" citing only a Finance fact is rejected (`relevance`); citing a Sales fact is accepted. If no fact exists in any named department the rule does not apply, because a related citation is impossible.
- *Direction*: a reference to an unspecified rise or fall ("the decline", "the recent increase") needs a cited fact with that verified direction, per direction mentioned. A mention is exempt only when the negation, condition or question applies to that mention itself ("no sign of the decline", "if the decline continues", "is the decline seasonal?"); a negator elsewhere in the sentence ("no one has explained the decline") does not exempt it.
Not changed, and still limits: extra citations beside a related one are tolerated for generic sentences (the metric-named rule keeps exact match, coverage and no extras); an accepted citation shows relatedness by department or direction, not that the fact supports the claim. Changed in G4.7: wholly generic text with no hook ("gather more data") is now rejected instead of accepted (see the G4.7 section).

**F5: flat-direction consistency (`semantic.ts`).** A flat finding means the relative change is under the catalog threshold, not that nothing moved. A directional claim about a flat metric is now judged against the finding and the raw values: equal values reject any up/down claim; a claim opposite to the raw movement is rejected; forceful language (strong verbs such as surged/soared/plunged, or an intensifier such as sharply/dramatically/significantly) is rejected when the relative change is defined. A truthful description of a small raw movement ("rose slightly" for +1%) is accepted. When the prior value is zero the engine labels the finding flat although the relative change is undefined; only the equality and sign rules apply there. Non-flat findings were untouched until G4.7 E18 (see the G4.7 section).

**F2: explicit discoverability.** Audit: the strict pipeline (`runStrictAnalysis` to `validateStrictOutput`) already used the generic `semanticScope`, which never infers a grant, but (1) a policy that omitted `discoverableMetrics` was indistinguishable from one that granted nothing, which is how the G4.1 runner silently lost its grant; and (2) the prototype facade `semanticGuards.semanticScope` defaulted to a grant derived from the departments of the records present, even for a strict scope. Now: `authorizeEvidence` reports `grantDeclared`; `runStrictAnalysis` refuses to run (blocked, nothing sent) unless the grant was declared (an empty array is a valid declaration); `validateStrictOutput` and `buildScopedMessages` throw if the grant is not an array; the facade throws for a strict scope without an explicit grant and keeps the department-derived default only for the legacy scope. Authorization of records is unchanged.

**E17 and E18: characterized in G4.6, decided in G4.7 (see the G4.7 section).** E17: an all-empty output was accepted, because the schema allows empty lanes; the G4.5 reasoning score rates it the weakest (0/10) but never gates. E18: qualitative magnitude ("rose sharply", "fell steeply") was accepted for non-flat findings; numeric and quantified magnitude (percent, doubled, a third) stay rejected.

**Unresolved policy decisions.** (1) Whether a zero-to-nonzero move should be classified flat by the engine at all (`computeFacts` labels it flat because the relative change is undefined); G4.6 works around it in the validator and does not change the classification or what Athena displays - out of scope for G4.7 by design. (2) Whether the causal-topic hook draws the right boundary: a sentence about causation with arbitrary citations still passes citation precision and relies on the causal guard alone.

## G4.7: citation precision, empty responses, sized strong language (offline; the strict path is still not promoted)
Three changes, all in the STRICT profile only. The legacy path, its detailed messages and the goldens are unchanged. `computeFacts`, fact classification, scoring and the G4.5 prompt are untouched, and zero-prior handling is unchanged. New diagnostic category `empty`; the public rejection is unchanged.

**Citation precision (`refConsistency.ts`).** A generic sentence (no available metric named) with no hook — no department or metric entity, no movement reference (even a bare movement noun, or a denied, conditional or interrogative one), no causal topic — is now rejected (`relevance`) instead of accepted. Causal-topic sentences ("the root cause is unknown") are already judged by the causal-integrity guard and still pass here; free-floating remarks belong in the missing-evidence lane, which carries no refs.

**E17: empty responses (`strictValidation.ts`).** A strict response with every lane empty is rejected (`empty`). The schema still permits empty lanes, any single entry in any lane passes this check, and every other rule still applies. Legacy behavior is unchanged.

**E18: sized strong language (`semantic.ts`).** Forceful movement language ("surged", "rose sharply") about a non-flat finding is supported only by a clearly large verified move: |change_pct| of at least five flat-thresholds (15% on the prototype catalog), rejected as `direction` below that. Plain descriptions ("rose", "fell"), zero-prior nulls, negated and flat-worded claims, monitoring directives, and process language without a direction word are unaffected; legacy behavior is unchanged.

**Calibration on the frozen fixtures.** Baseline exec: leads +50% and conversion -43.2% support strong language; closed deals -14.8% sits just under the 15% bar, so "plunged" is rejected while "fell" passes; acquisition cost +19.5% sits just above it. Quality-only exec revenue -4.7% rejects "plunged". The 5x multiple is a heuristic: mid-range moves still accept strong language. The closed-deals and acquisition-cost fixtures (E19, E21) sit 0.2pp and 4.5pp from the bar, so they are deliberate boundary coverage and are coupled to both that fixture data and `flatThresholdPct`: changing either silently flips them.

## G4.7a: review corrections (offline; the strict path is still not promoted)
An independent review of the G4.7 commit reproduced one defect and two boundary questions. All three corrections are STRICT-only or guard-internal; the legacy path, its detailed messages and the goldens are unchanged, and no authorization, discoverability or leak rule is touched.

**Intensifier binding (`semantic.ts`, corrects E18).** `strong` was computed by testing the +-24 characters around the direction word, which is proximity, not binding. Because E18 made `strong` load-bearing for every non-flat metric under the bar, an intensifier belonging to a neighbouring predicate rejected a truthful claim: with leads +6% and acquisition cost -50%, "lead volume rose." and "cac fell sharply." were each accepted, but "lead volume rose and cac fell sharply." was rejected (`direction`) because "sharply" fell inside the window around "rose". `intensifierSpan` now cuts that window back at any coordinator (`and`, `or`, `plus`, `nor`, `&`) separating the direction word from a neighbouring predicate. `SPLIT` already ends a clause at a comma and at "but"/"while"/"whereas", so those never needed handling. A coordinator joining an entity *chain* is not a predicate boundary, so "lead volume and cac rose sharply." still applies the strong claim to both subjects, and a strong *verb* ("surged") is still bound by the word itself and never by the window. This narrows `strong` only where the intensifier was not about the claim, so it also removes the same misattribution from F5 without weakening it: a flat finding still rejects forceful wording in its own predicate.

**Plural movement references (`refConsistency.ts`, corrects C12/G4.7).** `MOVE_NOUN` (the G4.7 anchor test) matched plurals but `GENERIC_MOVE` (the DIRECTION rule) did not, so "the declines" anchored a sentence while escaping the direction check: it could cite a fact that rose, where the singular "the decline" was correctly rejected. `GENERIC_MOVE` now accepts the plural, with `s?` outside the capture so the captured noun stays singular for the up/down lookup. Determiner-led plurals are therefore judged exactly like singulars, in both directions.

**Scoped-prompt guidance (`scopedPrompt.ts`).** The three G4.7 rules rejected output the prompt never asked the model to avoid, and one of them worked against the schema: `refs` are required on every interpretation and recommendation (`minItems: 1`), so a model writing a content-free recommendation was compelled to attach a ref and then rejected for it. The scoped system prompt now states that `missing_evidence` takes no refs and is where a remark that cites nothing belongs, that all three lanes must not be empty, that every interpretation and recommendation must be about what it cites, and that wording strength should match the size of each verified move. This is guidance only - no guard, threshold or category changed, and the prompt still carries no user text, record ids or hidden terms. It affects the strict prompt alone; the legacy prompt that `golden/combos.json` pins is a separate constant and is untouched.

**Known policy limitation, deliberately not narrowed: the causal-topic anchor.** Any generic sentence containing a causal-topic noun (cause, causes, causation, causality, causal) satisfies the G4.7 anchor test and may cite an arbitrary authorized fact - "consider the cause of this." citing any fact passes. Citation precision has nothing to compare a causal topic against and defers to the causal-integrity guard, which judges the causal framing but not whether the cited facts are related. Narrowing it would mean demanding a department or movement hook alongside the causal topic, which would reject the denied-cause framings the causal guard deliberately accepts ("the root cause is unknown.") because they carry no other anchor. It stays an open policy question rather than a defect.

**Remaining limits after these corrections.** A movement noun with no determiner still anchors a sentence without reaching the DIRECTION rule, because `GENERIC_MOVE` requires a determiner so that verbs and ordinary words are not read as claims ("gather more data on gains." passes with any citation). Subject binding is still proximity-based for the direction word itself, so unusual sentence structure can still bind a claim to the wrong metric or to none - the correction above fixes intensifier binding, not subject binding. The 5x multiple remains a heuristic.
